# SDV OTA Wave Transition 실험 결과

> **논문**: SDV OTA 웨이브 전환에서의 레이스 컨디션과 계층적 안전 전환 프로토콜
> **학회**: 2026 한국자동차공학회 춘계학술대회
> **저자**: 엄경문 (락코리아 / Rockkorea)
> **실험 조건**: Kubernetes v1.30.0 (Kind) + Istio 1.21.2, N=5 반복, mean ± std 보고

---

## 실험 환경

| 항목 | 구성 |
|------|------|
| 플랫폼 | Kubernetes v1.30.0 (Kind), control-plane 1 + worker 2 |
| 서비스 메시 | Istio 1.21.2, sidecar injection + mTLS STRICT |
| 추상화 모델 | auth → campaign → package → deploy (Uptane/OTA CE 기반) |
| 정책 계층 | Kubernetes NetworkPolicy (L4) + Istio AuthorizationPolicy (L7) |
| CRD | OTAWave (custom) + Python Controller |
| 반복 횟수 | N=5, mean ± std |

## 실험 3 — Readiness Probe 한계 (Policy Propagation Gap)

| 지표 | 측정값 |
|------|:---:|
| DENY 정책 적용 → Envoy 전파 완료 | **51.12 ± 0.18 초** |

### 전파 지연 타임라인

| 시각 | 이벤트 |
|:---:|------|
| t=0s | `kubectl apply` DENY 실행 |
| t≈0s | kubectl 리턴: 완료 (< 1초) |
| t≈0s | Readiness Probe: OK (즉시) |
| t=0.3~51s | 실제 트래픽: HTTP 200 통과 중 |
| t=51.12s | Envoy 전파 완료 (±0.18s) |
| t≥51.12s | 실제 DENY 차단 시작 |

> **핵심**: Readiness Probe는 Envoy 정책 전파(51초)를 감지하지 못한다. HSTP의 명시적 sync 대기(60초)가 필수.

D2 worst-case 기준, N=5 반복, attacker Pod로 Lateral Movement 시뮬레이션

| 지표 | No-Policy | Layer 1 only | Layer 1 + Layer 2 (HSTP) |
|------|:---:|:---:|:---:|
| 보안홀 지속시간 | 52.06 ± 0.48 초 | **0 초** | **0 초** |
| Attack Window | 52.06 ± 0.48 초 | **0 초** | **0 초** |
| Lateral Movement 차단율 | 25 ± 0 % | 81.34 ± 2.40 % | **99.1 ± 2.01 %** |
| 전환 중 요청 성공률 | 0 ± 0 % | 83.9 ± 1.76 % | **85.6 ± 2.14 %** |
| Transition Risk Window | N/A | 66.4 ± 1.82 초 | **63.0 ± 1.22 초** |

> **핵심**: 보안홀 52초 → 0초 (완전 제거), Lateral Movement 25% → 99.1% 차단, 요청 성공률 0% → 85.6%. **보안과 가용성은 Trade-off가 아니다.**

## HSTP 안전 비활성화 절차

서비스 1개당 4단계 순차 실행, D1 순서 (deploy → package → campaign → auth) 강제

| Step | 동작 | 설명 |
|:---:|------|------|
| 1 | **Drain** (8초) | 신규 요청 유입 차단, 진행 중 요청 완료 대기 |
| 2 | **Scale-0** | Kubernetes replicas=0, Pod 완전 제거 |
| 3 | **DENY** | Istio AuthorizationPolicy DENY 정책 apply |
| 4 | **Sync** (60초) | Envoy 전파 완료 대기 (실측 51초 + 안전마진 9초) |

- 서비스 4개 기준 전체 전환 시간: **약 272초**

## 주요 기여

1. **보안홀 정량화** — 비활성화 순서만으로 보안홀이 결정됨을 수치로 증명 (D2: 52초 → D1: 0초)
2. **Readiness Probe 한계 실증** — DENY 후 Envoy 전파까지 51.12초 갭 존재, K8s 표준 헬스체크는 전환 게이트로 사용 불가
3. **HSTP 설계 및 효과 검증** — OTAWave CRD + Python Controller + 마이크로세그멘테이션 통합으로 보안홀 0초 / Lateral 99.1% 차단 / 요청 성공률 85.6% 달성
4. **보안-가용성 양립 실증** — No-Policy D2 요청 성공률 0% → HSTP 적용 85.6%. 안전한 전환이 가용성도 향상
